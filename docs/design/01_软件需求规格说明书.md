# 生鲜冷链物流协同优化系统 软件需求规格说明书

## 1. 项目定位

本系统面向公网云端部署，服务于生鲜冷链配送业务中的订单管理、路径优化、三维装箱、仓库装车、司机执行与历史方案归档。系统由调度后台、仓库后台、司机移动端和管理后台组成，支持多人协同访问与长期数据保存。

系统目标不是单纯展示算法，而是形成可落地的软件平台：

- 调度员可以导入订单、运行优化、确认派车。
- 仓库员可以查看每辆车的装箱顺序、客户颜色、箱型代码并确认装车。
- 司机可以在手机端查看任务、导航、到站确认和异常上报。
- 管理员可以维护用户、车辆、箱型、成本参数、地图配置和系统权限。
- 所有订单、方案、路径、装箱结果和执行记录长期保存，可追溯、可复盘、可导出。

## 2. 用户角色

### 2.1 管理员

管理员负责系统基础配置和权限管理。

主要权限：

- 用户账号管理
- 角色权限管理
- 车辆配置管理
- 周转箱型号管理
- 成本参数配置
- 地图 Key 与安全配置
- 系统日志查看
- 历史数据维护

### 2.2 调度员

调度员负责订单、优化任务和派车方案。

主要权限：

- 导入订单
- 新增、编辑、删除未执行订单
- 地址解析与坐标校验
- 选择车辆运行路径优化
- 查看多种候选方案
- 确认最终派车方案
- 导出路线单、QGIS 文件、Excel/PDF 报表

### 2.3 仓库员

仓库员负责根据方案完成装箱。

主要权限：

- 查看待装车任务
- 查看每辆车三维装箱方案
- 查看客户颜色与箱型代码
- 查看逐箱摆放清单
- 确认装车完成
- 反馈装箱异常

### 2.4 司机

司机通过移动端执行配送任务。

主要权限：

- 查看本人配送任务
- 查看客户顺序、地址、电话、时间窗
- 一键调用地图导航
- 到达客户点确认
- 上传签收照片或异常照片
- 上报延误、拒收、交通异常等情况

## 3. 业务流程

### 3.1 订单导入流程

1. 调度员上传 Excel 或 CSV。
2. 系统解析订单字段。
3. 系统校验必填字段、时间窗、数量、重量、箱型。
4. 系统调用地理编码服务解析坐标。
5. 调度员确认异常订单。
6. 订单进入“待优化”状态。

### 3.2 路径优化流程

1. 调度员选择订单批次。
2. 调度员选择可用车辆。
3. 系统生成距离矩阵和时间矩阵。
4. 后端提交 OR-Tools VRPTW 异步优化任务。
5. 系统返回一个或多个候选方案。
6. 若存在 100% 准时方案，优先选择综合成本最低方案。
7. 若不存在 100% 准时方案，输出迟到时间最少方案和成本最低方案。
8. 调度员确认最终方案。

### 3.3 三维装箱流程

1. 系统读取每辆车的订单与周转箱信息。
2. 按客户、箱型、卸货顺序生成装箱计划。
3. 后端计算箱体坐标、排号、列号、层号。
4. 前端展示三维装箱图。
5. 同一客户用同一种颜色标识。
6. 周转箱型号用 A-F 字母代码标识。
7. 仓库员按装箱清单执行装车。
8. 仓库员确认装车完成。

### 3.4 司机执行流程

1. 调度员确认派车后，司机端生成配送任务。
2. 司机查看任务详情。
3. 司机按顺序导航至客户点。
4. 到达后点击“到站确认”。
5. 完成签收或异常上报。
6. 任务结束后系统归档实际轨迹和执行状态。

## 4. 功能需求

### 4.1 登录与权限模块

功能：

- 账号密码登录
- JWT 或 Session 鉴权
- 角色权限控制
- 菜单权限控制
- 操作日志记录
- 登录失败限制

验收标准：

- 未登录用户不能访问业务页面。
- 不同角色只能看到自己有权限的页面。
- 关键操作必须记录操作者、时间、IP、操作内容。

### 4.2 订单管理模块

订单字段：

- 订单号
- 发货地
- 收货地
- 收货地址
- 经纬度
- 箱型
- 箱数
- 单箱重量
- 起送时间
- 要求送达时间
- 客户联系人
- 客户电话
- 订单状态

功能：

- Excel/CSV 导入
- 手动新增订单
- 批量编辑订单
- 地址解析
- 坐标校验
- 时间窗校验
- 订单状态流转
- 历史订单查询

订单状态建议：

- 草稿
- 待优化
- 已优化
- 已派车
- 装车中
- 配送中
- 已完成
- 异常
- 已取消

车辆字段：

- 单箱重量

- 适用品类

### 4.5 优化任务模块

功能：

- 重新运行任务
- 保存候选方案

任务状态：

- 排队中
- 运行中
- 成功
- 失败
- 已取消

### 4.6 VRPTW 路径优化模块

硬约束：

- 车辆载重限制
- 车辆体积限制
- 周转箱数量限制
- 客户时间窗
- 车辆起终点
- 服务时间

优化目标：

- 第一目标：准时送达率 100%
- 第二目标：综合成本最低
- 兜底目标：若无法 100% 准时，输出迟到时间最少方案和成本最低方案

输出：

- 车辆路径
- 客户顺序
- 到达时间
- 离开时间
- 准时/迟到状态
- 迟到分钟数
- 车辆总里程
- 车辆总成本
- 总碳排放

## 5. 非功能需求

### 5.1 性能

- 1000 条订单以内的导入应在 10 秒内完成。
- 常规 50-200 个订单优化任务应异步执行，不阻塞页面。
- 优化任务运行期间前端应显示进度或状态。

### 5.2 安全

- 公网访问必须启用 HTTPS。
- 密码必须加密存储。
- 地图 Key 不应直接暴露在后端服务密钥中。
- 重要接口必须鉴权。
- 文件上传必须限制格式和大小。

### 5.3 数据可靠性

- PostgreSQL 定期备份。
- 优化方案不可被物理删除，只能归档。
- 派车后的订单修改必须产生版本记录。

### 5.4 可维护性

- 前后端分离。
- 算法模块独立封装。
- 成本参数、车辆参数、箱型参数可配置。
- 所有核心算法必须有单元测试。

## 6. 第一版 MVP 范围

第一版建议只做最关键闭环：

1. 登录与角色权限
2. 订单导入与管理
3. 车辆与箱型配置
4. OR-Tools VRPTW 优化
5. 方案保存与查看
6. 三维装箱展示
7. QGIS 导出
8. 司机移动端任务查看与到站确认

暂缓功能：

- 实时 GPS 轨迹
- 高级 BI 大屏
- 多仓协同
- 自动短信通知
- 复杂财务结算
